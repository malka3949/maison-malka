## מטרה

להרחיב מעבר לירושלים, לשלוט בעומס הזמנות, ולהוסיף אוטומציות שיווק — כולל **קמפיין מייל ידני (broadcast)** ללקוחות עם הסכמה.

## מה הפאזה עושה (גל 3)

1. **הרחבת אזורי משלוח**
   - הגדרת אזורים / ערים נוספות
   - תמחור משלוח לפי אזור
   - ולידציית כתובת לפי אזור שירות
2. **יכולות הזמנה מתקדמות**
   - הגבלת כמות הזמנות ליום (cap)
   - חלונות זמן למשלוח
   - הזמנות חוזרות / מנוי (אופציונלי)
3. **אוטומציות שיווק**
   - אימיילים אוטומטיים (תזכורת, חזרה ללקוח, סדרות — לפי אישור)
   - התראות מנהל (סף עומס)
   - pixel / רשתות (לפי צורך)
4. **קמפיין מייל ידני (broadcast)**
   - פירוט מלא: [../features/marketing-email-campaigns.md](../features/marketing-email-campaigns.md)
   - הסכמת דיוור נפרדת בקופה + הסרה מרשימה
   - קהל = מיילי הזמנות קודמות עם הסכמה פעילה בלבד

## בטווח

- ניהול אזורי משלוח בממשק מנהל
- cap יומי עם הודעה כשהתאריך מלא
- אוטומציות שיווק שאושרו בגל זה
- מודול קמפיין ידני נפרד ממיילי הזמנות (transactional)

## מחוץ לטווח

- ניהול מלאי אוטומטי מלא (גל 4)
- ניהול ייצור (גל 4)
- CRM מלא / התאמות מוצר מתקדמות (גל 4)
- אפליקציה native
- דריסת פאזת מוצר `08-admin-orders.md`
- ביצוע כ־Team Yuri Phase 8 (הוחלף — ראו roadmap)

## תוצאה ניתנת לבדיקה

```text
→ מנהל מוסיף אזור משלוח חדש
→ לקוח באזור מוגדר (מחוץ לירושלים) יכול להזמין עם תמחור נכון
→ תאריך שמגיע ל-cap יומי — חסום עם הודעה
→ מנהל שולח קמפיין רק לנמענים עם הסכמה; הסרה עובדת
→ (אם נכלל) אימייל אוטומטי / תזכורת נשלח לפי כלל מוגדר
```

## קריטריוני קבלה

- [ ] לפחות אזור משלוח נוסף פעיל מעבר לירושלים
- [ ] הגבלת הזמנות ליום עובדת
- [ ] קמפיין ידני: consented-only + unsubscribe
- [ ] מודול קמפיין מופרד מ-`sendOrder*`
- [ ] אוטומציה שיווקית אחת לפחות (אם נכללה בסקופ המאושר) עוברת E2E
