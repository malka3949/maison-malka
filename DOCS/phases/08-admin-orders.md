# פאזה 08 — ניהול הזמנות (אזור מנהל)

**קבוצה:** MVP  
**תלות:** פאזה 06, פאזה 07  
**מקור:** PRD §7 (ניהול הזמנות), §12 (סיכונים)

---

## מטרה

לאפשר למנהל לצפות בהזמנות, לעקוב אחר סטטוס ולנהל את תהליך המילוי.

## מה הפאזה עושה

1. רשימת הזמנות עם מיון לפי תאריך / סטטוס.
2. עמוד פרטי הזמנה:
   - פרטי לקוח (שם, טלפון, אימייל).
   - פריטים שהוזמנו.
   - אופן אספקה (משלוח/איסוף).
   - תאריך מבוקש.
   - הערות לקוח.
   - סכום ותשלום.
3. עדכון סטטוס הזמנה (לדוגמה: חדשה → בטיפול → מוכנה → נמסרה / בוטלה).
4. (אם נדרש) **אישור ידני** להזמנה לפני אישור סופי ללקוח.
5. בדחייה: בחירת סיבה מוגדרת או סיבה חופשית; הסיבה נשמרת ונשלחת
   ללקוח בשפת ההזמנה.

## בטווח

- צפייה בכל ההזמנות.
- פילטר לפי סטטוס ותאריך.
- עדכון סטטוס.
- הצגת פרטי לקוח מלאים.
- סיבת דחייה מאומתת בצד השרת ומוצגת בפרטי ההזמנה.

## מחוץ לטווח

- דוחות ואנליטיקה מתקדמת.
- התראות SMS/WhatsApp.
- ניהול ייצור.
- הגבלת הזמנות ליום (פתרון עתידי).

## תוצאה ניתנת לבדיקה

```text
→ לקוח מבצע הזמנה (פאזה 06)
→ מנהל נכנס לאזור הזמנות
→ רואה את ההזמנה החדשה ברשימה
→ פותח פרטים — רואה לקוח, פריטים, תאריך, הערות
→ מעדכן סטטוס ל"בטיפול"
→ בדחייה בוחר סיבה, והלקוח מקבל אותה במייל
```

## קריטריוני קבלה

- [ ] כל הזמנה מ-06 מופיעה ברשימת המנהל.
- [ ] פרטי הזמנה מלאים ונכונים.
- [ ] עדכון סטטוס נשמר.
- [ ] פילטרים עובדים (לפחות לפי סטטוס).
- [ ] לא ניתן לדחות ללא סיבה תקינה; הסיבה נשמרת ונכללת במייל.

## שאלות פתוחות

- **האם נדרש אישור ידני** לפני אישור הזמנה ללקוח?
- אילו סטטוסים בדיוק נדרשים?
- האם מנהל צריך לקבל התראה על הזמנה חדשה?
